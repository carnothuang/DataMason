## 三、验收中发现并修复的问题（1 项）

**M39 浏览器剧本流程向导竞态（测试脚本缺陷，非产品缺陷）**

- 现象：m39 第③步三次点「下一步」后，等待"流程已完成"超时；数据库取证为游标停在 2、记录 status 停在「已质检」、仅 2 笔 committed flow 日志（数据一致、无脏写）。
- 根因：剧本以 ant-message 成功 toast（文案含"完成"）作为每步等待条件；成功 toast 停留约 3 秒，第 2、3 次点击被**旧 toast 立即放行**，三个 advance 请求近乎并发，服务端按游标读到旧值拒绝最后一次（409）；而 409 错误文案"完成条件不满足"也含"完成"，再次被误判通过。
- 产品侧表现：服务端游标+完成条件校验正确拦截了并发越序推进（保守失败、数据无损）；手动顺序复现 advance API 返回 `done:true`，功能正常。
- 修复：`scripts/e2e/browser_e2e_m39.cjs` 第 3 步循环改为 `waitForResponse` 等待每次 advance 的真实 HTTP 响应并断言 200、末步断言 `done=true`，再重渲染。修复后干净环境重跑 24.0s 全项通过。

## 五、跳过项与已知限制（如实记录）

1. `test_a3_target_db.py` MySQL 真库用例——需设 `DATAMASON_TEST_MYSQL_URL`；该能力已由 `scripts/smoke_mysql.py` 在本机 MySQL 8 实测通过（开发期记录）。

3. `test_m1_settings.py` Redis 连通/真实 LLM 二选一门控——Redis 为选装件（DR-23），开发期本机 Redis 5.0.14（RESP2 兼容已修）PING 通过；真实 LLM 链路由 `scripts/smoke_qa.py`（REAL_LLM_M41_OK）与 run_e2e 实测背书。

其他已知边界（设计内，非遗漏）：
- 前端无独立单元测试（dashboard/ 无 vitest 配置），前端质量门 = tsc + vite build + Playwright 真浏览器；`maskText`/`isRenderableChart` 等纯函数由 m33/m42 浏览器用例覆盖。
- vite 构建有 chunk > 500KB 的体积告警（antd+echarts 全量），不影响运行，后续可做 manualChunks 拆包优化。
- 生产部署形态限单机/局域网（DR-17），无公网/容器强隔离；问数据仅只读 SELECT，无写入型问答；无工作流引擎/审批链（流程为向导式 v0）。
