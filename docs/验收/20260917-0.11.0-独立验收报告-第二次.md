根因已按 DR-28 修复：`deploy/service.py` 级联链补 `Attachment` 删除 + DATA_ROOT 守卫下的 `shutil.rmtree`。

### 🔴 D-2 附件预览存储型 XSS 面 —— ✅ 已封堵

伪造客户端 `Content-Type` 展开矩阵实测（服务端按扩展名强绑定）：

| 上传名 | 伪造 part 类型 | 落库 MIME | 预览 | 备注 |
|---|---|---|---|---|
| `note.txt` | `text/html` | `text/plain` | **200 `text/plain`** | 含 `CSP: default-src 'none'; sandbox` + `nosniff` |
| `NOTE.TXT`（大写） | `text/html` | `text/plain` | **200 `text/plain`** | 扩展名大小写不绕过 |
| `pic.svg` | `image/png` | `image/svg+xml` | **415** | 强制下载，不再 inline 执行 |
| `data.csv` | `text/html` | `text/csv` | 200 `text/csv` | 白名单内安全类型 |
| `page.html` | `text/plain` | — | **400** | `.html` 不在扩展名白名单 |
| `blob.bin` | `text/html` | — | **400** | 未知扩展名拒绝 |

所有类型下载一律 `Content-Disposition: attachment`。v1 报告的「已登录用户打开预览即在同源执行脚本」路径已不可达。

**残留观察（均为 P3，不阻塞）**
- **P3-1 写盘顺序**：`save_upload` 先 `write_bytes`、后判 `DM_UPLOAD_ALLOWED_MIME`。探针实测：当把 MIME 白名单收紧为 `image/png` 后上传 `.txt` → 返回 400 且 DB 无记录，但**磁盘残留 1 个未登记文件**。默认配置下该分支不触发（扩展名白名单内每个扩展都能映射到白名单内 MIME），建议把 MIME 判定前移到写盘之前。
- **P3-2 配置死条目**：`upload_allowed_mime` 默认含 `text/html`，而 `upload_allowed_ext` 不含 `.html` → 该条恒不可达（无安全影响，仅语义不自洽）。
- **P3-3 pdf 仍允许 inline**：浏览器内置 PDF 阅读器为沙箱环境，判定可接受；如需极致可一并改为 `attachment`。

### 🟠 D-3 停止态门控 —— ✅ 已修复

部署置 `stopped` 后，**8 个端点全部 409**：`POST /api/files`、`GET /api/files/{token}`、`.../preview`、`DELETE /api/files/{token}`、`GET .../rows`、`.../rows.csv`、`.../rows.xlsx`、`.../import/template`。
恢复 `running`（`POST /deployments/{id}/start`）后上述接口全部恢复 200/201 —— **未出现过度封锁**。

### 🟠 D-4 必填列未映射阻断 —— ✅ 已修复

- 只映射 `age`、缺必填 `name`：预览 `can_commit=false`、`blocking=['name']`、`valid=0`、`error_count≥1`。
- 提交侧二次守卫：`mode=skip_errors` 也被拒 **400「必填列未映射：name」**，库内 **0 行**（v1 的「先全绿后失败」不再出现）。
- 映射齐全时 `can_commit=true`、`blocking=[]`，提交成功。

### 🟠 D-5 导出列 / 上限 / 截断 —— ✅ 已补齐

- `rows.xlsx?cols=name` / `rows.csv?cols=name` → 表头**只剩 `name`**；`cols=name,age` → 200；`cols=nope` → **400「未知导出列」**（不再误报「未知过滤列: cols」）。
- 无 `cols` 时导出全列（id/name/age/created_by/…），**默认行为未回退**。
- `DM_EXPORT_MAX_ROWS=1` → CSV 与 XLSX 均返回 **`X-DM-Truncated: true`**；未超限为 `false`。
- 前端：`CrudListPage` 增加「导出列」多选，CSV/Excel 两个导出入口均携带 `cols`。

### 🟠 D-6 删表服务端二次确认 —— ✅ 已修复

- 被外键引用的表 + **正确 confirm** → **400**（守卫优先于 confirm，v1 关注的「先处理引用方」语义正确）。
- 未被引用的表：无 body / `{}` / `confirm:""` / 大小写不符（`Visit`）/ 不存在的表名 / 前导空格 → **全部 400**。
- 正确 `{"confirm": "<表名>"}` → **200**，meta 不再含该表，级联清理生效。
- E2E 剧本同步携带 `confirm`，真浏览器复跑通过。

   取得可信读数的方法：固定 `--basetemp` 到独立目录 + `--junitxml` 留证（并屏蔽该守卫的状态目录）。复跑结果：**266 passed / 3 skipped，exit 0，JUnit `tests=269 failures=0 errors=0 skipped=3`**，与修复跟踪声明完全一致。
