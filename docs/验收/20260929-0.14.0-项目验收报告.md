## 三、能力覆盖（M8 / 0.14.0）

- **M8-0 DDL 解析地基**：新增纯领域模块 `src/datamason/ddl/sql_import.py`。用 sqlglot 按目标方言 parse，仅接受建表 `exp.Create`；逐表抽取表名、列名、类型与长度/精度刻度、NOT NULL、内联/表级主键、UNIQUE、FOREIGN KEY ... REFERENCES 及目标表列、自增标记；类型归一到平台八类列（INTEGER/BIGINT/VARCHAR/TEXT/BOOLEAN/DATETIME/DECIMAL/FILE 口径，FILE 不从 SQL 产生）；缺省主键由系统补 `id`，复合/非平台类型主键拒绝；列解析错误先聚合、外键悬空随后校验，输出定位到表/列的可读错误清单。
- **M8-1 解析接口**：`POST /api/v1/deployments/manual/sql/parse`（body：sql / dialect / mode / target_connection_id?）。薄路由 + 服务，返回结构提案 spec_json 与 table_count；不执行、不落库、不调 LLM、不写 ai_generations；非法 SQL 经错误处理器映射为 400 + `{error, errors}`；link 模式直接拒绝。
- **M8-2 可视化补齐与双形态联动**：`ErCanvas` 提供 FILE 类型标记与校验状态角标，字段行编辑覆盖本版全部属性；草稿反生成 SQL 为确定性序列化（不保留手写注释与排版），SQL 与可视化共享同一份 SchemaSpec 草稿（DR-44）。
- **M8-3 ManualBuilder**：新增 `dashboard/src/pages/deploy/ManualBuilder.tsx`。Segmented（SQL/可视化）双形态；宽屏默认左右分栏（左 SQL、右结构）、窄屏退化为切换态（断点 760/1280 口径，Q1 定案）；SQL 编辑器基于 antd Input.TextArea 自研（等宽字体，颜色/尺寸取 `--fn-*`，零新依赖，DR-43）；错误列表定位、targetConnId（默认独立 SQLite）、系统名称/用途、beforeunload 提示；DeployWizard 的 `initialBuilder` 扩为 `"auto" | "hybrid" | "manual"`，Deployments 下拉接入第三项；全部新增文案入 `locales/{en,zh}.json` 且键对齐。
- **M8-4 确认落库**：草稿经 SchemaSpec 强校验后直接复用既有 `POST /deployments/confirm`；建库、建表、回读、页面派生、菜单注册、入口注册全部沿用；专业模式默认不勾选演示种子（Q2 定案），种子开关仍由操作人员控制；只改「造 spec 的过程」，不改「落库的过程」。
- **M8-5 版本 E2E 验收**：新增 `scripts/e2e/browser_e2e_m8.cjs`（六项验收）与 `scripts/e2e/serve_for_e2e_m8.py`（隔离无 LLM 环境）；真浏览器全绿 + 离线全量 pytest + 前端构建全绿 + 本报告。

## 四、验收中发现并修复的问题（5 项）

1. **解析回填后编辑列「整表误伤」**：后端 `spec_json` 的列不含前端专用 `key`，parseSql 直接 reset 进 reducer 后，updateColumn 的 `c.key !== action.key` 对同表所有列成立。修复：ManualBuilder.parseSql 中对每列经 `normalizeColumn({ ...c })` 补 key 后再构造草稿 reset。经截图与真浏览器验证。
2. **小画布节点几何重叠导致点击落空**：ErCanvas 环形布局在 520×420 画布（半径 90、节点宽 210）下节点重叠，force click 不绕过命中测试；且 Playwright 多层嵌套 `has` 过滤器在 SVG 内无法可靠解析（30s 超时）。修复：剧本改为直接定位 `svg text` 并按 DOM 顺序 `.nth(index)` 取目标（顺序与表顺序一致），用 `dispatchEvent(new MouseEvent("click",{bubbles:true,cancelable:true,view:window}))` 触发 React onClick，绕过命中测试。
3. **两类解析错误无法在同一次解析中同时出现**：sql_import 在 FK 校验前先对列解析错误 raise，「不支持类型」与「悬空外键」不能同现。修复：剧本段④拆成两次独立解析分别断言，再修正重解析。
4. **工作台侧栏非 antd Menu**：运行态工作台使用自研 Sidebar，导航项为 `button.dm-nav-item` > `span.dm-nav-item__label`。修复：段⑤菜单等待与点击改用 `.dm-nav-item` / `.dm-nav-item__label` 选择器。
5. **重连列默认命名与旧列名不同**：删线后重新建立关系，对话框按「被引用表名_id」生成新列名（引用 products → `products_id`），不复用被删的旧列名 product_id。连线语义与类型正确（INTEGER REFERENCES products），属产品默认命名行为而非缺陷；剧本断言同步改为匹配 `products_id`。

## 五、跳过项与已知限制（如实记录）

1. **4 项 skipped 为环境门控**（外部 MySQL/PostgreSQL 实连、需联网真实 LLM 等），非 M8 引入，沿用既有基线。
2. **专业模式仅对创建模式开放**：直连（link）模式维持只读红线（DR-45），段⑥已显式覆盖。
3. **用户 DDL 不直接执行**：SQL 经 sqlglot 归一化为 SchemaSpec，再由 Python 确定性生成目标方言 DDL 落库（DR-42）；反生成 SQL 不保留手写注释、排版与列顺序的个人偏好，切形态前有「按当前结构重排 SQL」确认。
4. **SQL 编辑器为自研受限形态**：无语法高亮/自动补全（DR-36/43，零新增前端依赖）；不支持存储过程/触发器/视图/非主键索引/分区表；JSON/BLOB/ENUM 等不支持类型在解析阶段明确报错，不做隐式降级，可按提示改用 VARCHAR/TEXT。
5. **草稿仅存浏览器内存**：刷新/关闭丢失（DR-37），有 beforeunload 提示；不做服务端持久化与多人协作。
6. **E2E 会创建带随机后缀的专业模式部署**：属测试数据，可在部署清单手动删除。
