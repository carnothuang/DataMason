## 三、能力覆盖（M5 / 0.11.0）

- **M5-0 地基**：`attachments` 元数据表；`deployment_menu_grants` 增 `actions_json`/`data_scope`（惰性回填，空=角色默认）；`ColumnType` 增 `FILE`（映射 VARCHAR）；请求体/上传/导入上限配置；`openpyxl` 依赖。
- **M5-A 结构演化（DR-27/DR-31）**：创建模式自建库增表/删表；归属列注入、外键指向真实主键、重名/物理同名拒绝；删表影响面提案（行数/FK 引用/页面/菜单/授权/流程/报表/种子）、被引用或被流程引用阻断、级联清理 + 物理 DROP；直连外部库仍拒（红线）。
- **M5-B 表单操作（DR-28/29/32/33）**：附件上传/下载/预览/删除（每部署独立目录、随机 token、扩展名白名单、大小上限、路径穿越防护、操作员行可见性）；FILE 字段控件与 FileChip；CSV/XLSX 导入四步向导（自动映射、必填/类型/长度/文件内重复/库内唯一/FK 校验、strict 回滚 / skip_errors、聚合 1 条 import 日志、模板下载）；XLSX 导出。
- **M5-C 权限细分（DR-30）**：功能 × 动作（查看/新增/修改/删除/导出/导入）+ 数据范围（全部/仅自己）可配置；服务端强制（`CrudRegistry.require_action` + `data_scope`），前端按权限裁剪；成员页「功能→动作 + 数据范围」配置；流程页授权自动展开其步骤页表；**修复**空表白名单退化为全量反射的越权隐患；API key 维持服务身份不受限并文档化。

## 四、验收中发现并修复的问题（1 项）

**空表白名单退化为全量反射（既有越权隐患）**：`CrudRegistry` 对 `tables=[]` 会退化为 `reflect(only=None)` 全量反射，导致「无任何表授权的操作员」实际可访问全部表；旧流程用例曾依赖该行为。修复为「空列表 = 明确无表可访问」，并把流程页授权展开到其步骤页表，使授权语义更正确。修复后相关回归（`test_m3_4_flow.py`、`test_m4_3_dashboard.py`）与全量测试均绿。
