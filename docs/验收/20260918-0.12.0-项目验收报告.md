## 三、能力覆盖（M6 / 0.12.0）

- **M6-0 地基（DR-34~38）**：`server/ddl/skeleton.py` 骨架中间规格（`SchemaSkeleton` 强校验、关系→外键列占位映射、唯一列名、`merge_skeleton_columns` 主键 id 与归属列系统补齐）；`server/llm/structure.py` 两段式生成（`generate_skeleton` 只产表集合+关系、`generate_table_columns` 逐表产字段，均 pydantic 校验 + 失败中文回喂重试，`temperature=0`）。
- **M6-1/M6-2 后端**：骨架提案路由与逐表字段路由；仅创建模式开放（link 模式 400，DR-39）；`overwrite`/`append` 两模式；外键只指向骨架内已存在表主键；未引导字段表识别；AI 埋点 `kind=deploy`。
- **M6-3 交互式 ER 画布**：`web/src/components/ErCanvas.tsx` 表节点增删/改名/业务名、环形+网格确定性布局、节点拖动微调、关系连线增删（弹层定外键列名，默认 `<目标表>_id`）；节点展开字段（业务名+类型+主键/外键/唯一），超过 6 列折叠为「…共 N 列」，空表标「待引导字段」；`hybridDraft.ts` useReducer 草稿单一数据源（连线由外键列派生，删列/改外键目标即时联动）。
- **M6-4 混合向导前端**：`DeployWizard` 输入页 Segmented 并列「全自动 / 混合·分步引导」（仅创建模式）；`HybridBuilder.tsx` 四步向导（意图 → 骨架图示 → 逐表字段 → 全量确认）；Step 3 逐表 NL 引导 + 手改（overwrite/append）；未引导表落库拦截并回跳；`beforeunload` + 关闭确认防丢草稿。
- **M6-5 确认链路（DR-38）**：`POST /deployments/skeleton/merge` → 合并为完整 `spec_json` → 复用 `POST /deployments/confirm`（建库/建表/页面/菜单/种子/入口全沿用）；合并校验失败返回可读 `errors` 并回画布定位节点。
- **零新增前端依赖（DR-36）**：画布与向导均为自研（SVG + antd），未引入图表/图形库。

## 四、验收中发现并修复的问题（1 项）

**混合向导意图表单跨步骤卸载导致落库丢失 `biz_name`**：`HybridBuilder` 的意图 `Form` 原先仅在 Step 1 条件渲染，进入 Step 2 后表单卸载、字段从 antd 注册表中移除；末步 `deploy()` 调用 `form.validateFields()` 返回值为空，`POST /deployments/confirm` 缺 `spec_json`/`biz_name` 而 400（真实浏览器实测：`{"error":"缺少 spec_json 或 biz_name"}`，且部署后无法进入工作台）。修复为将意图表单常驻挂载、非 Step 1 时以 `display:none` 隐藏，保证表单值在整条向导生命周期内可取。修复后 E2E 部署链路全绿。

## 五、跳过项与已知限制（如实记录）

1. **4 项 skipped 为环境门控**（外部 MySQL/PostgreSQL 实连、需联网 LLM 等），非 M6 引入，沿用既有基线。
2. **M5-C-5 字段级权限细分仍顺延**（DR-30）：`data_scope` 等能力已在 0.11.0 落地，字段级（列级）控制未纳入 M6 范围，保持顺延待排。
3. **E2E 使用确定性 LLM 桩**：验证的是链路正确性与 UI 行为，不评价真实 LLM 生成质量；生成质量依赖线上模型与 prompt 迭代。
4. **E2E 在开发默认工作区运行**：每次会创建带随机后缀的「M6混合订单E2E…」部署，属于测试数据，可在部署清单中手动删除。
5. **合并失败回画布定位**：已实现错误 → 节点聚焦；E2E 走的是成功主路径，失败定位由 `tests/test_m6_5_merge.py` 契约覆盖。
