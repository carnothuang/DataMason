## 四、验收中发现并修复的问题（0 项）

本版开发过程中一次定位并排除了一个**环境问题**（非代码缺陷）：8765 端口被一个早于本版代码启动的遗留服务进程占用，导致 E2E 服务无法绑定、浏览器请求命中旧代码而 404。清理遗留进程后 M7 E2E 全绿。已如实记录，不计入代码缺陷。

## 五、跳过项与已知限制（如实记录）

1. **4 项 skipped 为环境门控**（外部 MySQL/PostgreSQL 实连、需联网真实 LLM 等），非 M7 引入，沿用既有基线。
2. **字段控件/候选项为表级共享、仅布局按页面形态分离**：`form_field_configs` / `form_option_items` 无 `page_kind` 列（对齐技术方案数据模型），`form_layouts` 才有 `page_kind`。故"公开表单布局单独可控"已实现；控件类型与候选项在工作台与公开表单间共享。此为实现口径，测试 `test_m7_4_export_public.py::test_public_layout_scoped_by_page_kind` 已显式覆盖。
3. **`page_kind` 取值**：实现采用 `workspace` / `public`（服务默认 `DEFAULT_PAGE_KIND="workspace"`），与技术方案接口示例中的字面量 `"crud_list"` 不同，语义等价、前端不依赖该字面量。
4. **E2E 使用确定性 LLM 桩**：验证链路正确性与 UI 行为，不评价真实 LLM 生成质量；候选项生成质量依赖线上模型与 prompt 迭代。
5. **E2E 覆盖面**：M7 剧本覆盖单选/多选/日期时间/双列布局与三条写路径的服务端校验；附件控件渲染与公开表单最小暴露由既有 M5 附件 E2E 及本版单元测试（`test_m7_4_export_public.py`）覆盖。
6. **E2E 会创建带随机后缀的「M7表单E2E…」部署**：属测试数据，可在部署清单手动删除。

## 七、验收后修复：附件预览（2026-09-23）

**现象**：图片与文档附件预览报 `{"error":"FileNotFoundError: ... 'E:\\...\\server\\data\\deployments\\...'"}`。

**根因**：`DATA_ROOT` 默认 `./data`（及元数据库 `sqlite:///./datamason_meta.db`）相对**进程 CWD** 解析。当后端从 `src/datamason/` 目录启动时，读取路径变成 `src/datamason/data/...`，而文件实际上传在项目根 `data/...`，导致上传与读取落在不同目录。属"路径锚点依赖启动目录"缺陷。

**修复**：
1. `src/datamason/app.py` 新增 `anchor_path` / `anchor_sqlite_uri` / `_anchor_relative_paths`，在应用工厂中把相对 `DATA_ROOT` 与相对 sqlite 元数据库 URI 锚定到**项目根**（`Path(app.root_path).parent`）；绝对路径（测试/生产显式配置）原样保留。上传与读取从此与 CWD 无关，且兼容既有 `data/` 数据。
2. `src/datamason/files/routes.py` 下载/预览在文件缺失时返回 **404 可读提示**（"文件已丢失（可能未随数据一起迁移）"），并对 `send_file` 的 `FileNotFoundError/OSError` 兜底，不再 500。
3. 前端新增 `dashboard/src/components/FilePreviewModal.tsx`：图片内嵌 `<img>`、PDF `<iframe>`、文本/CSV 拉取后 `<pre>` 展示，其余类型（docx/xlsx 等）给出"暂不支持在线预览，请下载查看"并保留下载按钮；`FileChip` 与表单 `FileField` 的"预览"改为打开该弹窗（替换原先直接开新标签返回 415/JSON 的体验）。零新增依赖。

**验证**：新增 `tests/test_m7_files_preview.py`（5 项：锚定纯函数、绝对路径不变、缺失文件 404）；模拟从 `src/datamason/` 目录启动，`DATA_ROOT` 仍为项目根 `data/`，既有附件预览返回 `200 image/jpeg`。全量回归 **392 passed / 4 skipped**；前端 `npm --prefix dashboard run build` 通过。
