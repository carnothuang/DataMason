## 三、工程纪律（延续 0.10.0）

1. **严格按任务序推进**，后项依赖前项；每完成一项立即全量 pytest，全绿再进下一项。
2. **开发产物全部写在项目内**（`server/`、`web/`、`tests/`），个人目录/其他盘符不做工作区。
3. **DR 纪律**：发现规划与代码冲突时，先在《产品一页纸》§九 追加/更新 DR，再改代码或文档。
4. **零运行时依赖原则**：superset-lite/DBX 只是参考基线；不引入 superset 任何运行时包。本版新增依赖仅 `openpyxl`，前端不新增。
5. **环境纪律**：Python 一律用 managed venv（`C:\Users\carno\.workbuddy\binaries\python\envs\default`）；npm 装进 managed workspace，不用全局。
6. **测试分层**：离线 pytest 为每任务验收线；真实 LLM / 真浏览器 E2E 为里程碑验收线；MySQL/PG 真库门控单独标注。
7. **权限服务器端强制**：前端隐藏/置灰只做体验，安全边界一律在服务端；每个新写路由必须显式校验。
8. **文件安全清单**：白名单/大小/路径守卫/token 化，新增文件接口不得绕过；API key 白名单不放行文件接口。
9. **已知限制显式记录**：无法真库验证的项以方言单测代替并标注，后续补真库冒烟。
