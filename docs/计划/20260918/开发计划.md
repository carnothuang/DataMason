## 三、工程纪律（延续 0.11.x）

1. **严格按任务序推进**，后项依赖前项；每完成一项立即全量 pytest，全绿再进下一项。
2. **开发产物全部写在项目内**（`src/datamason/`、`dashboard/`、`tests/`），个人目录/其他盘符不做工作区。
3. **DR 纪律**：发现规划与代码冲突时，先在《产品一页纸》§九 追加/更新 DR，再改代码或文档。
4. **LLM 只产中间规格**：两段式（骨架/字段）都只产 JSON 中间态，Python 确定性映射与强校验；失败回喂重试沿用 `MAX_RETRY=2`。
5. **零新增运行时依赖**：本版前端**不新增任何依赖**（DR-36）；后端复用既有栈（pydantic/httpx），不引新包。
6. **环境纪律**：Python 一律用 managed venv（`C:\Users\carno\.workbuddy\binaries\python\envs\default`）；npm 装进 managed workspace，不用全局。
7. **测试分层**：离线 pytest 为每任务验收线；真实 LLM / 真浏览器 E2E 为里程碑验收线；MySQL/PG 真库门控单独标注。
8. **单一数据源**：混合模式草稿的字段定义是唯一真相，画布只是视图与编辑入口（DR-38）；任何路由/组件不得另起一套状态。
9. **已知限制显式记录**：无法真库验证的项以方言单测代替并标注，后续补真库冒烟。
