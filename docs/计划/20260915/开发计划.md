## 三、工程纪律（从计划文件延续的执行规则）

1. **严格按任务序推进**，后项依赖前项；每完成一项立即全量 pytest 验证，全绿再进下一项。
2. **开发产物全部写在项目内**（`server/`、`web/`、`tests/`），个人目录/其他盘符不做工作区。
3. **DR 纪律**：发现规划文档与代码冲突时，先在《产品一页纸》§九 追加 DR，再改代码或文档。
4. **零运行时依赖原则**：superset-lite/DBX 只是参考基线；不引入 superset 任何运行时包。
4b. **环境纪律**：Python 一律用 managed venv（`C:\Users\carno\.workbuddy\binaries\python\envs\default`）；npm 装进 managed workspace，不用全局。
5. **小步提交**：每个 M 任务完成即 git commit（信息含任务号），保持可回滚。
6. **测试分层**：离线 pytest（规格校验/DDL/反射/对账）为每任务验收线；真实 LLM/浏览器 E2E 为里程碑验收线。
7. **已知限制要显式记录**（如本机无 MySQL/PG 实例时以方言单测代替真库冒烟），M1 期间补真库验证。
