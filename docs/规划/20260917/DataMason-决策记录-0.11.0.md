# DataMason 决策裁决归档 — 0.11.0（DR-26 ~ DR-33）

> **性质**：0.11.0（M5）开发期的**唯一新裁决源**。0.10.0 的《产品一页纸》§九（DR-01~25）保持冻结、继续有效；本文件在其之上追加 0.11.0 新增裁决，冲突时以本文件为准（仅限 0.11.0 范围）。
> **合并去向**：下一版《产品一页纸》快照产出时，DR-26~33 并入其 §九，本独立文件即可归档。
> **维护规则**：沿用《产品一页纸》§九·四；任何跨文档概念改动，先在此追加 DR，再改规划/计划文档。

## 一、裁决总表

| DR | 走查问题 | 裁决（一句话） | 主要落点 |
|---|---|---|---|
| DR-26 | 里程碑编号只允许 M0–M4，无法表达新版本 | 里程碑编号向后扩展：**M5 = 0.11.0**，产品侧 **P4 = M5**；预留 M6/M7；子轨（M5-A/B/C）不是里程碑号 | 版本规划 §二·2.3、§六；开发计划 §二 |
| DR-27 | 「对已有数据库增删表」是否包括直连的外部库 | **只对创建模式自建库开放**；直连（link）模式维持「绝不 ALTER 外部库」红线；外部库结构变更作为后续独立 DR 议题（危险区形态）单独评估 | 版本规划 §三·3.3；技术方案 §三 |
| DR-28 | 附件怎么存（BLOB 落库 vs 文件 + 元数据） | **文件存储 + `attachments` 元数据表**；业务表新增逻辑类型 `FILE`（映射 VARCHAR 存 attachment id / id 数组），**不落 BLOB**；每部署独立文件目录；销毁级联清理 | 技术方案 §二·2.1/2.3、§四 |
| DR-29 | 批量导入的日志语义与「业务写必落日志」冲突 | 导入**聚合为 1 条** `action=import` 系统动作（摘要含文件/成功/跳过行数），**默认不逐行写**；逐行明细为默认关闭的开关 | 版本规划 §四·4.3；技术方案 §五·5.3 |
| DR-30 | 操作权限与数据权限存哪、字段级做不做 | 操作权限存 `deployment_menu_grants.actions_json`、数据范围存 `data_scope ∈ {'', all, own}`（惰性回填，空=角色默认，存量兼容）；**字段级（隐藏/只读）为可选增强**，启用闲置的 `crud_configs.ui_config_json`，可顺延 0.12.0 | 版本规划 §五；技术方案 §六 |
| DR-31 | 删表的风险控制无定义 | 删表前出**影响面提案卡**；**被外键引用或被流程步骤引用的表禁止删除**（保守，沿用列迁移保护哲学）；二次确认 + 建议先导出；物理 DROP + 级联清页面/菜单/授权/种子/配置 | 版本规划 §三·3.4；技术方案 §三·3.2 |
| DR-32 | Excel/CSV 导入（原 DR-16 的 P2+ 备选）何时做 | 需求信号已出现，**纳入 0.11.0 M5-B**；新增依赖 `openpyxl`；导入为「预览 + 校验 + 确认」提案式，永不盲写 | 版本规划 §四·4.3；技术方案 §五 |
| DR-33 | 文件/附件能力的安全边界未定 | 随机 token 命名 + 扩展名/MIME 白名单 + 大小上限（显式设 `MAX_CONTENT_LENGTH`）+ 路径穿越防护；**API key 通道默认不开放文件接口**；不引入在线预览/转换服务 | 版本规划 §四·4.1；技术方案 §四·4.3 |

## 二、需要工程特别注意的裁决细节

### DR-27「外部库只读」边界（为何不动 link 模式）
0.10.0 已多次裁决外部库只读（DR-05、M2-7/M2-8 守卫、`editor._assert_editable`），产品承诺是「数据资产始终是用户自己的，我们只搭操作层」。对外部库做 DDL 会破坏该承诺且无法在方言/权限/回滚上给出可靠保证。因此 0.11.0 的结构演化只覆盖**创建模式自建库**；若确有外部库改结构强诉求，另立 DR，走「显式危险区 + 影响面提案 + 二次确认 + 绝不隐式执行」形态单独评估。

### DR-29 导入日志（为何不逐行）
0.10.0 语义为「业务写必落日志」（两阶段 + 对账）。批量导入若逐行写，会瞬间把日志页淹没、失去可读性。故裁决：导入记 **1 条聚合动作**（`object_kind=table`，`action=import`），逐行明细作为默认关闭的开关提供。这是对日志「还原现场」目标的强化而非削弱。

### DR-30 权限存储与兼容
`actions_json` / `data_scope` 空值一律解释为「按角色默认」，从而升级不改变存量操作员行为；解析规则「同一用户对同一表多功能时数据范围取最宽」以 `resolve_access` 单一实现承载。
