## 一、为什么是这件事

### 1.1 现状：页面能自动派生，但「长什么样」几乎不由人

到 0.14.0 为止，平台已经能通过一句话、混合引导或纯手动 SQL 建表，并由 `_derive_pages` 确定性派生出列表页与公开表单（DR-07）。M7（0.13.0）进一步交付了表单设计器：可在新增/编辑表单内配置 **10 类控件**（单行文本、多行文本、数字、是否、单选、多选、日期、日期时间、关联选择、附件），支持候选项、只读/隐藏、字段顺序与分组，配置存入元数据库三表（`form_field_configs` / `form_option_items` / `form_layouts`），业务库零 DDL。

但从真实录数体验看，「页面」仍只是表结构的机械投影，存在两类明显断点。

### 1.2 真实缺口

| # | 现象 | 根因 |
|---|---|---|
| 1 | **控件形态不够用**：录入「是否启用」只能在下拉里选「是/否」，没有开关；填「满意度 1–5 星」「进度 0–100」只能敲数字；候选项一多（十几个状态），单选按钮组又长又占地方；省市区这类有层级的选项完全无法表达 | 控件清单在 M7 冻结为 10 类，且控件本身不可携带参数（范围、步长、星数、层级） |
| 2 | **录入看中文，存完看编码**：给字段配了单选（状态选「已下单」存 `1`），表单里确实显示中文；但一保存，列表页该列显示的是 `1`，不是「已下单」；筛选下拉同样是编码 | 选项的 value↔label 机制只覆盖了**录入控件与写校验**，列表回显侧没有消费它 |
| 3 | **关联字段存完只剩一个 id**：订单选了客户「华东贸易有限公司」存 `customer_id=7`，列表里这一列显示 `7`，看不出是谁 | FK 的 label 解析只存在于录入时的远程搜索，列表行没有把外键 id 批量还原成引用表显示值 |
| 4 | **整页布局完全不可配**：列表显示哪些列、列宽、行操作按钮、详情页长什么样、用卡片还是表格视图，全是代码写死的默认行为；同一种数据，不同使用者想看的侧重点完全不同，却没有一处可调 | 页面从表结构机械派生，`page_specs.layout_json` / `crud_configs.ui_config_json` 两个布局占位列自建库起就存在，一直无人消费 |
| 5 | **存量/历史数据没有对应选项时会怎样没有定义**：选项被改过、或导入的数据带了选项表之外的编码，回显行为不明确 | 缺少统一的「码→文」解析与兜底约定 |

### 1.3 0.15.0 的回答：更丰富的控件 + 全链路显文存码 + 页面级布局可配

> 在 **M7 表单配置体系之上增量扩展**（不另起炉灶），三条主线：
> ① 新增 **开关、滑块、评分、下拉选择、级联选择** 五类控件，并让控件可携带参数（最小/最大/步长、星数、层级选项）；
> ② 把「显示值 ↔ 落库值」映射从录入侧推广到 **录入、列表、筛选、详情** 全链路——录入看中文标签、库里存编码/外键 id、回显统一还原成中文，码无对应标签时安全兜底；
> ③ 页面级布局可配——参考 NocoBase 的「页面 → 区块 → 字段」模型，基于 **craft.js 画布 + react-grid-layout 自由拖拽**，把列表列/列宽/行操作按钮/详情布局/卡片视图/统计区块变成声明式可配置，布局存入元数据库。

一句话：**0.14 解决了「怎么把库建得专业」，0.15 解决「建出来的页面录得顺、看得懂、摆得开」**。表单控件与显文存码全部使用 antd 5 已内置组件（不新增依赖）；页面布局画布引入 craft.js 与 react-grid-layout 两个 MIT 依赖（本版放开依赖纪律，见 DR-52）。全程维持 M7 既定纪律——业务库零 DDL、零配置零变化。

## 二、版本范围与边界

### 2.1 范围内（M9 三主线）

| 主线 | 能力 | 一句话 |
|---|---|---|
| **M9-A 丰富表单控件** | 新增 switch / slider / rate / select / cascader 五类控件，控件可携带参数，设计器可配置并实时预览 | 同一列，多种更贴切的录入形态 |
| **M9-B 显文存码通用化** | 选项类与外键类字段的 value↔label 映射，统一驱动录入、列表回显、筛选、详情；码无标签时兜底原值 | 录入看中文，库存编码，回看还是中文 |
| **M9-C 页面级布局可配** | 参考 NocoBase 页面→区块→字段模型：声明式区块布局（列表列显隐/列宽/行操作按钮/详情布局/卡片视图/统计区块）+ 自由拖拽摆放；craft.js 画布 + react-grid-layout 实现 | 页面从「代码写死」变成「声明式可配、可拖拽」 |

### 2.2 明确不做（边界）

- **不做 NocoBase 级插件体系 / 事件流 / 服务端 hooks**：页面布局只做「布局与展示配置」，不做可编程插件、不做块内脚本与联动事件流。
- **不做整站级页面自由编排的无限扩展**：页面布局配置**只作用于既有派生页面形态**（列表页/详情页/公开表单页）与新建的仪表盘页；区块类型收敛为有限集（列表表格 / 详情 / 统计卡 / 自定义内容），不开放自定义渲染组件注册。
- **不引入 amis / Appsmith / ToolJet / Budibase**：amis 自带一套 UI 体系与数据域，与 antd 5 双轨冲突、体积最重；后三者是整套平台，无法作为 npm 组件嵌入，均不在本版。
- **不直接复用 NocoBase 前端**：其客户端是 Application/Plugin 架构、强依赖后端 API，官方不提供独立设计器包；本版只借鉴其「页面→区块→字段」模型与 Formily Schema 的协议写法（见 §三/DR-51）。
- **不改变 CRUD 数据流**：布局 schema 只描述「怎么展示」，数据仍走既有 `crud` 引擎与 `api.ts` 通道；schema 不引入新的数据请求范式。
- **业务库零 DDL**：所有布局配置只落元数据库既有 `page_specs.layout_json` / `crud_configs.ui_config_json` 两列（本版起真正消费）；不改业务表结构、不新增业务列。
- **级联（cascader）本版只做单选、存末级值**：不做多级联选（存路径数组）、不做异步动态加载层级、不做任意选中父节点。层级选项在设计器内静态维护。
- **不做「选值自动带出」联动**：如选了客户自动回填地址/电话这类跨字段联动，本版不做。
- **不做导入字段映射 / 选值映射**：CSV/XLSX 导入的列映射沿用现状，本版只消费选项做写校验，不做导入向导里的码表转换编辑器。
- **导出默认仍导原始值**：CSV / Excel 导出沿用现状导出落库值（编码/id），不在本版改为导标签（见 §八 Q2）。
- 沿用既有边界：表重命名迁移、跨库结构迁移、数据清洗、存储过程/视图/触发器、新测试框架等不做。

## 三、能力设计

### 3.1 新增控件总览

| 控件 type | antd 组件 | 适用列类型（相容矩阵扩展） | 落库值 | 携带参数 |
|---|---|---|---|---|
| `switch` 开关 | `Switch` | BOOLEAN | 1 / 0 | 无（固定开=1 关=0） |
| `slider` 滑块 | `Slider` | INTEGER / BIGINT / DECIMAL | 数值 | min、max、step |
| `rate` 评分 | `Rate` | INTEGER（allow_half 时 DECIMAL） | 整数（或半星小数） | max_stars（默认 5）、allow_half |
| `select` 下拉选择 | `Select` | VARCHAR/TEXT/CHAR + 数值 + BOOLEAN（同 radio） | 选项 value | 无（复用候选项） |
| `cascader` 级联选择 | `Cascader` | VARCHAR/TEXT/CHAR（末级 value 为字符串） | 末级选项 value | expand_trigger（click/hover，默认 click） |

设计原则与 M7 一致：

- **零配置零变化**：`control_type` 为空仍走 `default_control_type`；新增参数均有默认值；存量表单不配任何新控件时，渲染、校验、回显与 0.14 完全一致。
- **相容矩阵双真相源对齐**：后端 `CONTROL_COMPAT`（`forms/spec.py`）与前端 `compatibleControls`（`FormControlRenderer.tsx`）同步追加五类，不允许单边新增。
- **布尔列仍默认 `boolean`**：`switch` 是可选项而非新默认，避免改变存量表单外观。
- **零新增依赖**：五类控件全部为 antd 5 内置组件（Switch / Slider / Rate / Select / Cascader），仅需在渲染器 import 中追加。

### 3.2 控件参数（control config）

在字段配置上引入「控件参数」，仅对需要参数的控件有意义；参数按控件类型做强校验，非法参数保存即拒绝。

| 参数 | 适用 | 校验 |
|---|---|---|
| min / max | slider | 必填数值；min < max |
| step | slider | 正数；INTEGER/BIGINT 列 step 必须为正整数，DECIMAL 列允许小数 |
| max_stars | rate | 1–10 的整数，默认 5 |
| allow_half | rate | 布尔，默认 false；为 true 时该列必须是 DECIMAL（半星需小数落库） |
| expand_trigger | cascader | `click` / `hover`，默认 `click` |

switch、select 不携带参数。控件参数在保存时随字段配置一起入元数据（落在 `form_field_configs` 一个 JSON 串列，见 §3.7），读配置时原样回传，渲染器据此初始化组件。

### 3.3 层级候选项（cascader）

为在扁平表 `form_option_items` 上表达层级，给候选项增加一个可空的 **`parent_value`**：

- `parent_value` 为空表示顶层；非空时必须引用**同一字段内另一个选项的 value**。
- 校验：不允许引用不存在的父值；不允许出现环；同层级内 value 仍唯一。
- 渲染：组装成 antd Cascader 需要的 `{value,label,children}` 树；本版只允许选择末级节点。
- 落库：选中末级选项的 **value**（字符串）。
- 回显：由 value 沿 parent 链向上拼出完整路径标签（如 `浙江省 / 杭州市 / 西湖区`）展示。

层级深度不做硬上限，但受单字段选项总数 `MAX_OPTIONS_PER_FIELD=200` 约束；超出按既有规则拒绝。

### 3.4 写校验扩展（forms/service）

在既有 `_validate_value`（radio/checkbox/date）基础上按控件追加，全部为确定性校验，不调 LLM：

| 控件 | 写校验 |
|---|---|
| switch | 值必须为 1 / 0（沿用 BOOLEAN 口径） |
| slider | 必填时非空；数值落在 [min, max]；满足 step 口径；类型与列一致（整数列不得提交小数） |
| rate | 值落在 1..max_stars；allow_half=false 时必须整数，true 时允许 0.5 的倍数 |
| select | 值必须在候选项 value 集合内（同 radio） |
| cascader | 值必须是某一**末级**选项的 value（父节点 value 不可作为落库值） |

校验失败返回业务可读消息（含字段业务名与允许范围），由蓝图映射为 4xx，不写库。

### 3.5 显示值↔落库值映射通用化（M9-B 核心）

把散落在 radio / checkbox / FK 三处的局部机制，统一为一张「字段 → 解析器」的回显规则，供四个消费点使用：

```
                ┌─── 选项类：form_option_items（含层级 parent_value）
码（库存值） ──┤                                                        ├──► 标签（展示）
                └─── 外键类：引用表显示列（按 id 批量解析）
```

| 消费点 | 现状 | 0.15 行为 |
|---|---|---|
| 录入控件 | 已显示 label | 不变；新控件接入同一套选项 |
| 列表回显 | **直接 `String(v)` 显示编码/id**（`CrudListPage.tsx` 第 139–146 行） | 选项类用 value→label 映射；层级拼完整路径；FK 用批量标签；都查不到时兜底显示原始值 |
| 筛选 | 选项字段按编码填、按编码显 | 静态选项字段的筛选输入改为下拉（显示 label、提交 value，过滤仍按库存值）；FK 筛选维持现状 |
| 详情/编辑回显 | 编辑表单 initialValue=value，控件显 label | 不变；详情布局在 M9-C 中复用同一解析 |

**映射只是「读侧渲染」，绝不改变库存值**：库里始终存 value/编码/id，任何回显、筛选都不在写路径上替换数据，与既有只读红线一致。

**兜底约定**：当值为 NULL 显示 `—`；值非空但在选项/FK 标签中查不到对应（历史数据、选项被删、导入值）时，**原样显示库存值**，不报错、不阻断；选项配置整体读取异常时沿用 M7 的 `degraded` 降级（表单可录、列表退回原值）。

### 3.6 外键批量标签解析（后端）

FK 的码→文无法靠静态选项完成，需查引用表。为避免列表逐行查询（N+1）：

- 在工作台列表数据装配处（`workspace/service` 组装 rows payload），对当前页**可见的外键列**收集去重 id，按列分别做一次 `WHERE <pk> IN (...)` 批量查询，取引用表显示列（沿用现有 ref 显示列推断：名称/标题类列优先，回退主键）。
- 结果以 `ref_labels: { 列名: { "<id>": "标签" } }` 附在本页 rows 响应中随数据返回；仅当前页、仅可见 FK 列，每页 20 行，查询量有界。
- 业务库引擎按请求创建、`finally` dispose（沿用既有纪律），不长期持有。
- 直连（link）模式下该解析同样是只读 SELECT，不触碰 DR-27 红线；表单 UI 规格配置对直连表亦可用（只改展示、不改结构）。

### 3.7 数据模型变更（元数据库，幂等）

仅元数据库，沿用 `create_all_lazy` + 列回填（幂等 `ALTER TABLE ADD COLUMN`）：

- `form_field_configs` 增加一列存放控件参数 JSON（可空，默认空）；不拆新表。
- `form_option_items` 增加 `parent_value`（可空字符串，默认空）以表达层级。

布局配置**不新增表、不新增列**，直接消费既有两列：`page_specs.layout_json`（页面级：区块排布与拖拽坐标）与 `crud_configs.ui_config_json`（表级：列表列/行操作/详情布局）。业务库不做任何变更。模型与回填逻辑同一次提交修改，老库升级时自动补列、默认空值，零配置行为不变。

### 3.8 公开表单一致性

公开访客表单（`public`）复用同一份字段控件配置：新增五类控件与显文存码在公开表单同样生效；候选项、只读/隐藏、必填口径与工作台一致。本版不为 workspace / public 分别维护控件配置（沿用现状）。公开页的布局可配只开放声明式区块的**安全子集**（隐藏列/列序/详情布局），不开放自由拖拽（见 §3.10）。

### 3.9 页面级布局可配（M9-C 核心）

#### 3.9.1 模型：页面 → 区块 → 字段（参考 NocoBase）

参考 NocoBase 的页面（Page）/ 区块（Block）/ 字段（Field）三级模型，映射到 DataMason 既有资产：

| NocoBase | DataMason 映射 | 说明 |
|---|---|---|
| 页面 | `page_specs` 一行 | 每页一条；`layout_json` 承载页面布局 |
| 区块 | 区块节点（表格/详情/统计卡/自定义内容） | 布局 JSON 中的节点；每页可多个、可拖拽 |
| 字段 | `crud` 反射列 + `form_field_configs` | 区块内引用表字段，控件与显文存码复用 M9-A/M9-B |

页面区块类型（有限集，本版收敛）：

| 区块类型 | 内容 | 可配项 |
|---|---|---|
| `table` 列表表格 | 现有列表页（CrudListPage） | 列显隐/列序/列宽、行操作按钮显隐、默认视图（表格/卡片）、筛选区显隐 |
| `detail` 详情 | 行详情展示 | 字段显隐/分组/只读、布局列数 |
| `stat` 统计卡 | 单值统计（总数/某列求和/某值计数） | 统计口径（count/sum/avg）、目标列、标题 |
| `html` 自定义内容 | 静态说明/标题/分隔（只读 Markdown/文本） | 内容文本 |

`table`/`detail` 区块引用**既有表格的 meta**（列清单来自 `crud` 反射），`stat` 区块引用表+列做聚合，`html` 区块纯展示。所有区块的数据仍走既有 CRUD 通道。

#### 3.9.2 schema 与落点

- 页面级布局 JSON（页面 → 区块 → 字段，含区块类型/引用表/字段配置/拖拽坐标）存入 **`page_specs.layout_json`**。
- 表级展示配置（列表列显隐/列序/列宽/行操作按钮/详情字段布局/默认视图）存入 **`crud_configs.ui_config_json`**。
- schema 写法参考 Formily Schema 2.0 协议方言（`x-component` / `x-component-props` / `x-decorator` 风格），但不引入 formily 运行时，仅作为「布局描述 JSON」由自研渲染器消费——这样未来如需迁移到 Formily/NocoBase 生态，协议可复用。
- 约定：`layout_json == "{}"` / `ui_config_json == "{}"` 表示未配置，走 `_derive_pages` 默认派生行为（零配置零变化）。

#### 3.9.3 画布设计器（craft.js + react-grid-layout）

- **craft.js**（`@craftjs/core`，MIT）：画布式节点树——把 antd 组件（表格/详情/统计卡/内容卡）包成可拖拽节点，提供画布、物料面板、属性面板的框架；与 antd 5 零样式冲突（画布即 antd 组件）。
- **react-grid-layout**（MIT）：区块在页面上的自由拖拽/缩放/压实（行列栅格坐标），与 craft.js 配合：RGL 管「区块在页面的位置」，craft.js 管「区块内的字段与属性编排」。
- 设计器能力：
  - 从物料面板拖入区块 → 画布上摆放（RGL 栅格）/ 自由缩放；
  - 区块内字段配置（列显隐/列序/列宽、详情字段分组、统计口径）复用 M7 设计器的表格化交互风格；
  - 实时预览 + 保存（写 `layout_json` / `ui_config_json`，走既有页面配置接口）；
  - 入口：列表页/详情页/公开页的操作区新增「布局」按钮，仪表盘类页面直接进画布。

#### 3.9.4 运行态渲染与降级

- 工作台/公开页装载页面时读取 `layout_json` / `ui_config_json`；有配置按 schema 渲染，无配置走默认（与 0.14 一致）。
- schema 解析异常整体降级为默认渲染（沿用 M7 `degraded` 思路），**绝不让布局配置崩溃阻塞录数**。
- 直连（link）模式：布局配置只影响展示，不触碰 DR-27 只读红线；统计区块的聚合为只读 SELECT。

#### 3.9.5 与既有能力衔接

- 卡片/表格视图切换：现状是 `localStorage` 全局持久化（`datamason:` 前缀）；本版把**默认视图**纳入 `ui_config_json` 每表可配，用户在页面上手动切换仍即时生效。
- 显文存码（M9-B）与控件（M9-A）在列表回显、详情、筛选的成果，直接成为 `table`/`detail` 区块的字段级展示基础。
- 列表「我的记录」数据范围、操作/数据权限（`deployment_menu_grants`）不受布局影响；行操作按钮显隐只影响入口可见性，权限判定仍在后端。

## 六、验收标准

**离线（pytest，每任务验收线）**

- 五类新控件与相容矩阵：合法列可配、不相容列拒绝；前后端口径同源（以同一组样本断言）；
- 控件参数：min/max/step、max_stars/allow_half、expand_trigger 的合法组合通过、非法组合保存即拒绝；
- 层级选项：悬空父值、自引用/成环、把父节点作为落库值分别拒绝；末级值通过；
- 写校验：slider 越界/错步长、rate 超星数/整数列提交半星、select/cascader 值不在选项内分别拒绝；
- 映射服务：选项与层级码→文、FK 批量标签正确；批量查询次数有界（非逐行）；值无标签时兜底原值、不抛错；
- 布局 schema：`layout_json` / `ui_config_json` 读写与校验；非法区块引用表/列、非法统计口径拒绝；`"{}"` 走默认派生；存量数据兼容（空配置行为不变）；
- 回归：零配置字段的渲染/校验/回显与 0.14 一致；直连模式只读、无任何写入通道。

**真实浏览器（Playwright，里程碑验收线）**

- 设计器为 BOOLEAN 配开关、为数值列配滑块（设范围步长）、为评分列配 Rate、为长选项列配 Select、为地址列配三级 Cascader；
- 录入：开关/滑块/评分/下拉/级联均显示中文或可视形态，提交后**查业务库验证库存的是编码/数值/末级 id**，而非标签；
- 列表：上述列显示中文标签与完整层级路径，FK 列显示引用表显示名称而非 id；
- 筛选：静态选项字段筛选下拉显示标签，选择后按库存值正确过滤；
- 编辑：再次打开时控件正确还原到已选状态；
- 兜底：构造一个选项外的历史值，列表原样显示、不报错；
- 布局：从物料面板拖入「表格 + 统计卡 + 内容卡」区块，自由拖拽摆放；配列显隐/列宽/隐藏行操作按钮；保存后运行态按布局渲染、统计卡数值正确；
- 默认视图：某表在 `ui_config_json` 配默认卡片视图，重进列表页即卡片视图；
- 公开表单：五类控件与显文存码对访客生效；公开页布局安全子集生效、无拖拽入口；
- 直连表：可配置展示控件并正确回显、可配布局，全程无结构/数据写入。

**版本级**：独立验收报告（`docs/验收/2026xxxx-0.15.0-项目验收报告.md`），M9 验收线全绿；默认交付线为离线全量 pytest 全绿 + `npm --prefix dashboard run build` 通过。

## 八、风险与开放问题

| 风险 / 开放问题 | 说明 | 缓解 / 决策点 |
|---|---|---|
| **R1 FK 批量解析性能** | 一页多列外键、引用表很大时，多次 IN 查询仍有成本 | 仅当前页、仅可见 FK 列、id 去重；显示列尽量走索引主键；不逐行查（DR-50） |
| **R2 craft.js 停滞风险** | craft.js 0.2.x 已两年未更新，社区有维护疑虑 | DR-52 分层设计：RGL 管区块坐标、craft.js 管节点树，渲染层与 craft.js 解耦；若停更可替换为 dnd-kit 自研节点树 |
| **R3 画布体积与首屏** | craft.js + RGL 增加运行时体积 | 设计器按需加载（动态 import，仅「布局」入口触发）；运行态渲染不打包设计器代码；构建时记录体积增量 |
| **R4 布局 schema 可维护性** | 自由拖拽产物（坐标、嵌套）可能难读难改 | 画布保存时做 schema 归一化（排序、去重、约束到 RGL 栅格）；提供「还原默认布局」入口（清空 JSON 回 `"{}"`） |
| **R5 降级与回归** | 布局配置解析异常可能阻塞录数 | 沿用 M7 degraded 思路：解析异常整体降级默认渲染，绝不让配置崩溃阻塞业务；空配置行为与 0.14 一致 |
| **R6 cascader 层级编辑成本** | 扁平 parent_value 在表格里维护多层级，交互可能繁琐 | 设计器提供「按层级缩进 + 指定父项」的最简编辑，先支持固定 2–4 层；不做拖拽树；复杂层级引导用「省/市/区」类模板 |
| **R7 历史/脏数据回显** | 选项变更或导入带来选项外编码 | 按 DR-49 兜底原值，不报错；后续可在设计器列出「未被引用/引用不到」的选项做治理，本版不做 |
| **R8 参数与列类型错配** | 整数列配小数 step、半星落在整数列 | 保存时强校验（M9-0），不相容组合拒绝并说明 |
